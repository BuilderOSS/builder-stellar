# Local workspace semantics

- `/create` is available without a wallet. Identity is name, symbol, and image only. Description and independent auction/marketplace choices follow. Governance includes an absolute vote threshold and queue delay. Review and deployment use the same validated configuration.
- Drafts live in `localStorage`, not the backend. They are not shared, encrypted, or synchronized across devices. Multiple tabs in this browser receive storage updates; concurrent draft edits are last-write-wins, not collaboration.
- Drafts are scoped to network, Manager address, and wallet. Guest drafts can be resumed by a connected wallet and become wallet-owned when deployment is prepared. Other wallet drafts stay saved but hidden. Home DAO preferences are separately scoped the same way, including a guest preference.
- The prior `dao.create-dao.v4` key is migrated in place. Existing identity, description, absolute governance values, and membership choices survive. Old data URL images become local previews with a valid deployed-image fallback. The retired purpose text is deliberately not part of the current configuration.
- Image selection saves a square, bounded local thumbnail. Upload requires an authenticated session and uses the existing Pinata signed-upload and completion APIs. Only the completion API's HTTP gateway URL becomes deployment metadata. A preview is never silently deployed.
- Create deploys paused contracts in **Setup**. The immutable configuration, cryptographic u64 nonce, predicted addresses, and signed transaction hash are saved before transmission. Recovery checks the saved hash or actual pending Manager state. Unknown outcomes never create a new nonce or silently sign again. Wallet rejection can retry the same prepared snapshot; a confirmed chain failure is distinct from unknown confirmation.
- Web Locks prevent concurrent creation, launch, and artwork signing from different tabs. Every draft mutation reads the durable collection first. Creation also writes an independent, scope-keyed per-draft recovery snapshot that form autosave never touches, so a racing stale autosave cannot erase its signed hash. Submitted and confirmed creation records cannot be deleted; duplicate creates a fresh unsigned draft without copying receipts.
- The scoped `/api/dao/[daoId]` endpoint is only used after on-chain confirmation. A 404 timeout is directory delay, not failed deployment. A confirmed deployment remains resumable while the directory is unavailable.
- **Launch** is a separate explicit action. Readiness checks actual Token supply/owner/live state, actual Manager pending ownership, and both modules' current payment assets against the assets pinned at creation. Founder supply must be nonzero. `auctionEnabled === null` during Setup does not block readiness. The user reviews exactly the selected modules and any registered platform minter; the minter address is pinned for signing. Launch and artwork transactions also keep independent receipt keys that preference/plan autosave never overwrites.
- Artwork Setup preserves starter collections, durable directory uploads, layered previews, and keyboard-accessible ordering. The Metadata binding's 30-item call limit is enforced with explicit, separately signed batches. Local artwork plans and their in-flight hashes are scoped and saved. Existing artwork is never overwritten. Configure before founder minting; tokens minted before artwork may need the documented Metadata `regenerate` workflow.
- Clearing browser storage removes drafts, preferences, and transaction recovery records. Storage/quota/read errors are shown and block signing. No page starts a signing operation on mount, claims success from simulation, or pretends to offer collaboration.

The unowned `lib/dao-deployment-validation.ts` still imports the old store shape but is not used by creation. Its owning agent should delete or replace it; its type-only bridge has no persisted fields or no-op actions. Artwork/CSV types still imported by unowned preview and CSV utilities remain exported until those utilities are moved.
