A module is an add-on that gives a tribe a way to sell, auction, or give out memberships. Every tribe has the same four core parts: its membership token, its artwork, its voting rules, and its treasury. Modules are added to these, and each tribe chooses which ones it has.

For crypto natives: a module is a separate contract registered on the tribe's Token contract. Each module belongs to that tribe alone. It is not shared with other tribes.

## The three built-in modules

| In the app | The module | What it does |
|---|---|---|
| Daily auction | Auction module | Sells one new membership at a time to the highest bidder. The next auction starts when one ends. Each sale pays the treasury. |
| Market | Marketplace module | Lets members resell their memberships, and lets the tribe sell new ones at a fixed price from quick-buy pools it opens by vote. |
| Invite lists | Claims module | Gives memberships to a published list of wallets, free or at a price. Anyone can check the list. |

## How a tribe chooses its modules

The create flow asks how people join. Each answer sets the modules the tribe starts with:

- **Daily auction**: the auction.
- **Auction + resale**: the auction and the market.
- **Fixed-price sales**: the market.
- **Invite only**: invite lists.

A tribe can add or remove modules later. Both happen in one place: Manage → Membership → Modules.

## Mint allowances

A module that creates new memberships needs a mint allowance: the number of tokens it may still mint. This caps what any module can do. The auction gets an allowance with no limit, because it mints one token per auction. The market gets an allowance for each pool the tribe opens. "Change allowance" on the module's row raises or lowers it: directly by the launch admin during setup, and by vote after launch.

The largest allowance the contract stores (4,294,967,295) means no limit. Raising an allowance adds to it, and a raise that would pass the largest value stops there, so the module then has no limit. Lowering an unlimited allowance by any amount above zero sets a limit again.

If a vote lowers the auction's allowance to zero while an auction is running, that auction still ends and settles as usual. The auction then pauses instead of starting the next one. A later vote can raise the allowance and then resume auctions.

Some modules hold memberships without votes. The auction and the market are marked "Holds tokens without votes", and the tokens they hold never count towards quorum.

## Adding a module

Choose "Add a module", pick a tile, fill in its settings, and review the steps.

- **After launch**, adding a module is a proposal. The steps run together when it executes: create the module, register it on the token, and, where needed, grant its allowance and open it. The switch that opens it, "Start the first auction when this passes" for an auction or "Open it when this passes" for a market, is on by default. The review shows the address the module will have, and checks the plan against the chain before you add it.
- **During setup**, the [launch admin](/reference/glossary#launch-admin) adds it directly, with one signed transaction.

A tribe can have one module of each built-in kind and at most 16 modules in total. During a launch drive, modules can't be changed.

## Removing a module

Only a vote can remove a module, so a module can be removed only after launch. Before you add the removal to a proposal, the app checks what the module still holds: memberships, open listings, a running auction, or open invite lists. It warns about each one and offers clean-up steps for the same proposal, such as closing a pool and sending its memberships back to the treasury.

A module that holds memberships without votes, such as the auction or the market, can be removed only once it holds none. Otherwise the proposal fails when it runs. Removing it while it holds them would leave those memberships unable to move in a tribe with locked memberships. Before the removal, the same proposal can:

- **Auction:** pause auctions and cancel the running one, which refunds the top bid and sends the token to the treasury.
- **Market:** close and sweep each pool, which sends unsold memberships to the treasury. Before the proposal runs, each open resale listing must be cancelled by its seller, or must end and be cleared (anyone can clear an ended listing, which returns the token to its seller). The market contract can also return a listing to its seller, and send the treasury a membership that someone transferred to it directly before such transfers were refused, by vote while the market is paused. The app doesn't offer these two steps.

If the clean-up you choose won't empty the module, the app says so and doesn't add the removal to your proposal.

Nobody can send a membership directly to the auction or the market. Each takes memberships only through its own actions: the auction mints the membership it sells, and the market takes a membership when someone lists it. In a tribe whose memberships are not locked, a member can still list a membership while the vote is open, because the proposal pauses the market only when it runs. The removal then fails. To remove a market that members may still list on, pause it in an earlier proposal. A proposal that returns listings also fails if a seller cancels one of them first.

Removal ends the module's allowance and any right it had to move memberships. A module that holds memberships with votes, such as a claims module, can be removed while holding them, and it keeps them.

## Modules from outside Tribe Builder

After launch, the contracts let a tribe register another contract as a module by proposal. The "Add a module" sheet offers only the three built-in modules. A module that Tribe Builder did not deploy shows "Not deployed by Tribe Builder". Tribe Builder can't check its code, and its records are not covered by one-click [storage renewal](/concepts/storage-and-renewal). Its mint allowance still caps what it can mint.

Any deployed contract can be registered this way, including a member's smart-contract wallet. A plain Stellar account (a G-address) can't. The wallet doesn't have to agree. If a vote registers a contract wallet as a module that holds memberships without votes, its memberships stop counting as votes at once, for the wallet and for anyone it delegated to. The tribe can't recover those memberships by vote, and the wallet can still move them out, even while memberships are locked. The member gets the votes back by moving the memberships to another wallet. While the wallet is registered, nobody else can send it memberships. Before voting for a "Register a module" proposal, check what the address is.
