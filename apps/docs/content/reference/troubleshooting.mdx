Start with the message the app shows. Most messages say whether anything was signed or submitted. If a message ends with a code, look it up in [Error messages](/reference/error-messages).

## Connecting your wallet

| What you see | What to check |
|---|---|
| "You declined the request in your wallet, so you're not signed in." | You refused the sign-in request. Press Connect wallet again and approve the request. Signing in is free and moves nothing. |
| "Switch your wallet to Testnet and try again." | Your wallet is on another network. Change it to Testnet in the wallet's settings, then connect again. |
| A banner says "Switch your wallet to Testnet" | You're signed in, but your wallet changed network. You can still read everything. Switch the wallet back to vote, bid or propose. |
| "This wallet can't report its network" | Some mobile wallets don't tell the app which network they use. Check in the wallet that it is set to Testnet before you approve anything. |
| "The wallet signed with a different address." | The wallet has more than one account, and it signed with another one. Select the same account in the wallet, then connect again. |
| "Too many sign-in requests. Try again in a few minutes." | The app accepts a limited number of sign-in requests in a short time. Wait a few minutes. |
| "Authentication challenge has expired." | The sign-in request is valid for 5 minutes. Connect again and approve it sooner. |
| The top bar stays on "Check wallet" | Close the wallet window, reload the page, and connect again. If it happens again, report it. |
| Your wallet isn't in the list | Make sure the wallet's browser extension is installed and unlocked, then reload the page. See [Wallets and Stellar basics](/concepts/wallets-and-stellar). |

## Sending a transaction

Every transaction is checked against the network before your wallet asks you to approve it. If that check fails, nothing is signed.

| What you see | What to check |
|---|---|
| A message that "nothing was signed or submitted" | The check found a problem first. Read the message, fix the cause, and try again. Nothing changed on chain. |
| "Fund your account on this network, then retry." | Your account has no XLM on testnet, or not enough for the network fee. Fund it with Friendbot. See [Your first 10 minutes](/start/first-10-minutes). |
| "This action would pay about … XLM in network fees" | The app refuses to sign a transaction with a fee above 50 XLM, because a fee that high usually means shared contract code needs renewing. Nothing was signed. Report it to the Tribe Builder team. |
| "Some of your onchain records were archived" | Your membership or balance records expired after a time without activity. Approve the extra restore transaction, which costs a small fee, and the app continues. See [Storage and renewal](/concepts/storage-and-renewal). |
| "Confirmation is still pending" or "Confirmation is unknown" | The transaction was sent, but the app hasn't seen its result. This is not a failure. Open the transaction hash in [stellar.expert](https://stellar.expert/explorer/testnet) before you try again, so you don't send it twice. |

## Something doesn't appear

| What you see | What to check |
|---|---|
| A confirmed bid, vote, claim or proposal isn't shown yet | The app reads from an index of the chain, which can take a few seconds to catch up. Wait, then refresh. The transaction itself is already on chain. |
| "The tribe index is unavailable right now" or "Index unavailable" | The index can't be reached. Try again in a moment. If you have a tribe's link, open it directly. |
| You can't find a tribe | Search Discover by the tribe's name or any of its contract addresses. A tribe made on dev.tribes.build doesn't appear on tribes.build, and the other way round. See [Contract addresses](/reference/contract-addresses). |
| "This tribe is still in setup. Bidding opens once it launches." | The tribe hasn't launched. Auctions and most actions open at launch. See [Setup versus launched](/concepts/setup-and-launch). |
| "Too many requests. Wait a minute, then try again." | Claims and transaction checks accept a limited number of requests from one internet connection each minute, and so does artwork, which may not load until then. Wait a minute, then reload. |
| An image in a proposal or comment shows as a link | Images show only when they are stored on IPFS. Open the link to see the image at its own address. |
| A tribe says its contracts were archived | Its storage ran out. Anyone can restore and renew it from Manage → Storage renewal. The wallet that signs pays the fee. Until then, the parts that use that storage don't work. See [Storage and renewal](/concepts/storage-and-renewal). |

## Proposals

| What you see | What to check |
|---|---|
| You can't make a proposal | You need at least the tribe's votes needed to propose, counted at the ledger before you propose. See [Write a proposal](/guides/proposals/write). |
| You can't vote | Voting power is counted when the proposal is made. Tokens or delegations you received afterwards count only on later proposals. Voting may also not be open yet, or already closed. See [Vote](/guides/proposals/vote). |
| A passed proposal hasn't run | Someone has to queue it, then execute it after the safety delay. Any wallet can. See [Queue and execute](/guides/proposals/queue-and-execute). |
| Execute fails | One of its actions can't run, so nothing changed. The message names the failing action's code. The proposal stays queued until it expires, so the tribe can fix the cause, for example by funding the Treasury, and anyone can try again. |
| The composer warns about the order of actions | Some actions need another action earlier in the same proposal, such as "Pause auctions" before an auction setting change. Follow the warning. See [Choose actions](/guides/proposals/actions). |
| "Links must start with https://, http://, or ipfs://." | The discussion link uses another kind of address. Use a web or IPFS link, or remove it. |
| A draft is missing | Drafts are saved in the browser where you made them. Open the same browser on the same device. |

## Auctions, market and claims

| What you see | What to check |
|---|---|
| Your bid is rejected | It must be at least the starting price, and beat the current bid by the tribe's minimum bid increase. The auction must also still be running. See [Bid in an auction](/guides/auctions/bid). |
| "You were outbid and the refund couldn't be sent automatically." | Your XLM is waiting for you in the auction. Claim the refund from the auction page. See [Auction refunds](/guides/auctions/refunds). |
| "We couldn't check for a refund" | The app couldn't read the auction. Try again before you assume there is no refund. |
| The auction ended but no new one started | Someone has to settle it. Any wallet can. See [Settle an auction](/guides/auctions/settle). |
| You can't sell or transfer your membership | The tribe may have locked memberships, or a listing for the token may already exist. See [Sell a token](/guides/marketplace/sell). |
| A purchase fails after you reviewed it | The price, the fee or the payment asset changed. Review the new terms and try again. |
| "Claim simulation did not pass" | Check that the connected wallet is the one on the list, that you haven't already claimed, that the list is still open, and that you have XLM for fees. See [Claim](/guides/claims/claim). |

## Reporting a problem

If none of this helps, note:

- the page address;
- the exact message, and any code;
- the transaction hash, if there is one;
- your wallet and whether you use it in a browser or on a phone.

Then report it to the Tribe Builder team. Never share your wallet's secret key or recovery phrase. No one from Tribe Builder will ask for it.
