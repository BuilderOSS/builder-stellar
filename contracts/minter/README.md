# Shared Minter contract

One platform Minter supports multiple DAO Tokens. It is deployed separately from the six DAO modules and has per-token allocations, not a global stored administrator.

## Interface

```text
mint_batch(token_id: Address, recipients: Vec<Address>, amounts: Vec<u128>)
set_merkle_root(token_id: Address, root: BytesN<32>)
mint_merkle(token_id: Address, recipient: Address, amount: u128, proof: Vec<BytesN<32>>)
set_allowlist(token_id: Address, addresses: Vec<Address>, fixed_amount: u128)
mint_allowlist(token_id: Address, recipient: Address, amount: u128)
```

Here `token_id` means the **Token contract address**, not an NFT number. Every operation requires a Live token. Token owner authorizes batch/configuration operations; after launch that owner is Treasury, so owner actions require governance. Claim operations require recipient auth and Minter Token mint authority.

Batch accepts 1–100 recipient entries with matching amount vectors and calls Token's vector batch mint. This recipient count is not a 100-token supply cap. Merkle proofs have at most 32 siblings. The leaf is `sha256(recipient_xdr || amount_be_u128)`; each internal node hashes its sorted pair. Merkle and allowlist claims have separate rounds; replacing one allocation starts that method's round, allowing earlier recipients to claim again in that new round. Allowlist amounts must equal the configured amount.

Before launch founders mint directly through Token; Minter is not a setup tool. Manager registers the platform address and launch can grant it authority using pinned `expected_minter`. Only DAO governance can revoke that Token grant afterward.

No Minter binding package is generated by the current seven-package generator. [Implementation](src/contract.rs), [storage](src/storage.rs), [events](src/events.rs). `cargo test -p minter`. [Database Minter projections](../../docs/DATABASE_SCHEMA.md).

The web dynamically loads/checks the deployed Minter spec for claimant preparation
and signing. It separates current RPC eligibility from indexed history. The current
allocation admin form only validates review descriptors; its methods are not yet
registered for shared governance submission. See [web capabilities](../../apps/web/README.md).
