2. Add a module

Two screens in one sheet. Choose, then set up and review on the same screen, so there is nothing to remember between steps. Click through it: pick a module, change a field, and watch the steps and the button count follow.

When this passes, in order

After the vote and a 5 minute safety delay. If any step fails, none of them run.

    Checking against the chain…

    What the demo is showing

    One decision per screen. Screen 1 asks only "what". Screen 2 asks only for what the contract needs, and the review rewrites itself as you type.
    The address is the surprise. The market will live at a fixed address that exists before the vote. Showing it up front lets a reviewer open it, and the same address is what the proposal page decodes later.
    The check is automatic. No "validate" button. It runs when the fields are valid. It simulates the first step on the live chain and checks the rest against what the chain says now, because later steps depend on earlier ones inside the same vote and cannot be simulated alone. The button stays disabled until it passes, and a second check runs on submit.
    The button says what it does. "Add 3 actions to your proposal", never "Submit". The count follows the toggles. In Setup the same button reads "Add the market module" and signs.
    Disabled tiles say why, in words under the tile: already have one, factory paused, 16 modules reached.

    Desktop. The same sheet floats centred at 560px. The sticky action bar keeps its 14px padding so the button radius (10) sits concentric inside the sheet corner (24).

    4. Remove a module

    Removing is one call, but doing it well is a short checklist: tokens the module still holds would become that contract's own votes, and nobody can cast them. The sheet reads the live state, offers the clean-up as steps in the same proposal, and still lets the tribe go ahead, because anyone could otherwise block a removal by sending the module a token.

    Variants

    Nothing in the way. A claims module with no tokens and no lists collapses the checklist to two green rows, and the button reads "Add 1 action to your proposal".
    An auction mid-sale. The checklist offers "Pause and cancel the running auction first", which refunds the top bid and sends the token to the treasury. Without it, the token stays with the auction.
    An open claim list. One amber row: unclaimed allocations stop being claimable. No clean-up step exists, so there is no toggle, only the words.
    A custom module. It reads the token's balance and votes for the address and shows those two rows. It cannot know more, and says so: "We can only see what the token knows about it."
    Before launch. The menu item is disabled with its reason: "Only a vote can remove a module, so this works after launch."
    Warnings never block.Every amber row can be ignored, and the review that members see on the proposal page repeats them.

    6. Motion and details

    Per DESIGN.md, motion is intentional and there are only two authored moments. This feature adds none. It leans on the primitives, and spends polish on the states where people wait or decide.

    WhereWhatWhy
    Sheet240ms in, 180ms out, --ease-drawer (the Sheet primitive)Occasional, so it animates. No custom curve.
    Tiles, buttons, menu itemsscale(.96) over 160ms on press; hover only under (hover:hover) and (pointer:fine)Every pressable listens the same way.
    Choose to setupInstant swap, focus moves to the new headingKeyboard Enter picks a tile, and keyboard actions never animate. Going back and forth should never wait.
    Row menu150ms, opacity and scale(.97) from the button's cornerPopovers scale from their trigger, never from centre.
    Check statusSpinner, check and alert swap with scale .25 to 1, opacity, blur 4px to 0, cubic-bezier(.2,0,0,1) in 160msA state change you wait for. Words change with the icon, so motion is never the only cue.
    Steps that appear or vanishNone. Rows update in place.People toggle these while reading. Motion would make the list feel like it is moving under them.
    Added to the draftThe existing callout fades in, 150msReuses the pattern on this page.
    Reduced motionScale and blur removed. Opacity and colour stay.Fewer, gentler animations, not none.

    Polish details

    Concentric. The sheet is 24, the action bar sits 14px in, the buttons are 10. On mobile the sheet's bottom corners are square, so only the top corners round.

    Optical. The plus in "Add a module" is nudged 0.5px right of the geometric centre; the tile icons align to the first line of the title, not the middle of the tile.

    Icons. One library, 1.5px stroke beside regular text, 2px only beside semibold. They take colour from text with currentColor.

    Surfaces. Tiles are tone on tone, with a border only when selected. Rows use dividers, never cards inside the card.

    Accessibility

    The tiles are a radio group with arrow-key movement. A disabled tile stays focusable and announces its reason.

    The check status is a polite live region. Errors are announced once, next to their field, and focus moves to the first one on submit.

    The sheet traps focus and returns it to the menu item that opened it. Every control is at least 44px; chips are labels, not controls.

    Every chip pairs a word with its colour. Addresses are mono and copyable through the existing Address component.
