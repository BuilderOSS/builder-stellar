# Proposal actions

Every action the proposal composer can queue, the contract call it becomes, and what must hold for that call to succeed when the proposal runs. A proposal runs as `Treasury.execute`: the Treasury calls `Governor.consume`, then makes each call in order as the direct caller, so "Treasury" below means the Treasury's own authorization of that exact call. Any failing call reverts the whole proposal, which stays Queued and can be retried until it expires.

Sources: the handlers in `apps/web/src/lib/proposal-actions/`, encoding in `apps/web/src/lib/proposal-supported-calls.ts`, and the contracts' entry points and error enums (codes are `common::error::codes` blocks: common 70xx, Manager 71xx, Token 72xx, Metadata 73xx, Auction 74xx, Governor 75xx, Treasury 76xx, Marketplace 77xx, ClaimMinter 78xx).

**Tests.** Every row has a fixture in [`contract-spec.test.ts`](../apps/web/src/lib/proposal-actions/contract-spec.test.ts): the queued action encodes to the XDR the bindings produce for the expected arguments, reads back, and keeps its proposal id when re-encoded. The same file's negative table checks each validator against the contract's bounds. Order and prerequisite rules are in [`proposal-action-identity.test.ts`](../apps/web/src/lib/proposal-action-identity.test.ts) (the composer shows them as warnings, or errors when the call is certain to fail). [`bindings-drift.test.ts`](../apps/web/src/lib/bindings-drift.test.ts) checks the bindings against the compiled WASM. None of this executes a call on chain.

## Known gaps

- The proposal page re-encodes indexed arguments to check the proposal id. `AuthNode.args` is `Vec<Val>` and the indexed form drops its types, so a proposal with `treasury-authorize` cannot be re-encoded there ("Untyped Val argument"). Pinned with `it.fails` in `contract-spec.test.ts`.
- `analyzeProposalDraft` reads the tribe's indexed state where it has it (auction paused, membership switches, built-in modules). A custom module or a running pool's market pause state is not indexed, so those rules say "unless" rather than block.
